Run dash — 친구 동행 및 백그라운드 복구

운영 적용 순서
1. supabase/migrations/202611140010_social_running.sql을 기존 마이그레이션 009까지 적용된 Supabase 프로젝트에 실행.
2. main 코드 푸시 및 Vercel 배포.
3. 두 정식 계정으로 러닝 시작 → 친구 찾기 → 닉네임 검색 → 초대 → 상대 수락 확인.

사용 방법
- 정식 계정 러닝 화면의 친구 찾기 버튼 사용. 익명 체험은 동행/진행 복구를 지원하지 않음.
- 위치 공개 기본 OFF, 초대 받기 기본 ON. 수락한 동행 상대에게는 위치 공유.
- 공개 러너는 3D 화면과 미니맵에서 확인. 검색한 공개 러너는 위치 보기로 카메라 이동.
- 초대는 60초 후 만료. 거절/취소, 동행 종료, 차단/해제 지원.
- 동행 상대는 옆 차선에 표시. 각자 거리, 체력, XP는 별도. 순간 합류를 기록으로 가산하지 않음.
- 위치는 약 3초마다 RPC로 갱신하며, 갱신 사이 이동은 클라이언트에서 보간. GPS 사용 안 함.
- 접속하지 않은 시간이 60초를 넘거나 둘 중 하나가 러닝을 끝내면 동행 종료.

진행 복구
- 프레임과 독립된 경과 시간으로 시뮬레이션 진행. 숨겨진 탭에서 지연된 시간은 복귀 시 반영.
- 브라우저에 1초마다, 서버에 10초마다 체크포인트 저장.
- 새로 로그인하면 활성 러닝 세션과 일치하는 저장본 중 최신 것을 선택해 이어서 달리기 제공.
- 쉬던 상태는 쉬던 상태로, 달리던 상태는 경과 시간을 반영해 복원. 오프라인 중 보급품 자동 획득은 없음.
- 새 러닝을 시작하면 기존 활성 러닝을 대체. 기존 서버 XP 검증 및 중복 지급 방지 유지.
- 브라우저를 완전히 닫은 동안 서버 작업이 계속 도는 방식은 아님. 다음 복원 시 경과 시간을 계산.

서버 변경
- 위치/차단/초대/동행/복구 데이터를 위한 신규 테이블 6개.
- 모든 신규 테이블 RLS 활성화, 직접 조회/쓰기 차단. 필요한 RPC만 authenticated에 허용.
- 계정 정지, 초대 당사자, 수락 권한, 중복 동행, 만료, 차단 관계를 서버에서 검사.
- 현재 루프 코스에서 동작하는 첫 버전. 서로 다른 코스 선택 기능은 현행 서비스에 없음.
- 운영 API 비용: 사용자당 위치 갱신 약 분당 20회와 체크포인트 저장 약 분당 6회. 이용 규모가 커지면 위치 방송을 별도 Realtime 채널로 전환할 수 있음.
- 기존 데이터 삭제/초기화나 기존 기록·XP 계산 함수 교체는 하지 않음. 완주 시 신규 소셜 상태를 정리하는 트리거가 추가됨.

검증
- npm test: 29개 통과.
- 프로덕션 빌드 통과. 3D 청크 크기 경고는 기존과 동일하게 남음.
- 테스트: 백그라운드 진행/회복, 일시정지 복구, 완주 중복 방지, 비공개 위치, 제3자 수락 위조, 초대 만료/거절/취소, 동행 중복, 차단, 다른 계정 체크포인트 접근, 오프라인/완주 정리.
- 운영 DB와 브라우저 실사용 검증은 완료하지 않음. Windows 브라우저 도구가 현재 URL을 판별하지 못해 UI 자동 검증을 중단함.

현재 운영 DB 적용은 자동 승인 검토에 의해 차단되어 있으며, 명시적인 운영 DB 변경 승인이 필요함.
