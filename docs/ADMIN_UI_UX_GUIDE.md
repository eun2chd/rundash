# Run dash 관리자 UI/UX 디자인 가이드

작성일: 2026-11-16 (같은 날 개정). 적용 대상: 회원 관리, 문의, 채팅 신고, 설정, 변경 이력.

## 1. 목표와 디자인 원칙

운영자가 사용자를 찾고, 계정 상태를 이해하고, 변경 영향을 확인한 뒤 작업하도록 설계한다.
공통 기준은 `DESIGN_GUIDELINES.md`이며 Pretendard, 크림·베이지 배경, 어스 그린 계열 버튼과 오렌지 포인트를 계승한다.
첨부 예시의 흐린 회색 보조 글씨와 Tailwind 의존성은 도입하지 않는다.

### 타이포그래피와 색상 (필수)

- 글꼴은 CDN으로 불러오는 Pretendard(`pretendardvariable-dynamic-subset`)를 사용한다. 관리자 화면과 포털로 띄우는 모달·메뉴에도 같은 글꼴을 지정한다.
- 본문, 간단한 설명, 표 데이터, 입력값, placeholder는 **#212121 · Medium(500)**.
- 화면 제목, 섹션 제목, 표 헤더, 강조 수치는 **#212121 · Bold(700)**. 800 이상은 쓰지 않는다.
- **연한 회색과 회색 계열 글자 색은 사용하지 않는다.** 비활성은 배경 #e4e0d8, 점선 테두리, 커서로 구분하고 글자는 #212121을 유지한다.
- 상태 배지는 글자를 #212121로 두고 배경·테두리 색으로 구분한다.

## 2. 전체 화면 영역 구조

관리자는 카드들을 좁은 중앙 컨테이너에 모으지 않는다. 화면 전체를 헤더·사이드바·콘텐츠로 나눈다.

- 헤더는 화면 전체 너비를 사용한다. 공통 헤더의 최대 너비 제한을 관리자 화면에서 해제한다.
- 헤더 아래 왼쪽 사이드바는 232px, 오른쪽 콘텐츠는 남은 너비와 높이 전체를 사용한다.
- 영역 사이 간격이나 둥근 바깥 카드 대신 테두리로 구분한다. 콘텐츠 안쪽 작업 여백만 24px 확보한다.
- 사이드바와 콘텐츠는 각 영역 안에서 스크롤한다. 관리자 화면의 공개 사이트 푸터는 숨긴다.
- **콘텐츠 영역은 헤더 영역과 본문 영역으로 분리한다.** 헤더(높이 68px, 흰 배경, 아래 테두리)에는 아이콘과 메뉴 제목만 두고 고정한다. 본문만 스크롤한다.
- 헤더에 새로고침 버튼과 "러너의 계정 상태와 활동을 확인하고…" 같은 설명 문장을 두지 않는다. 목록은 검색·필터·페이지 이동 때 다시 조회한다.
- 페이지를 넘기는 동안 기존 목록을 흐리게 유지하고 새 목록으로 바꾼다. 빈 화면으로 깜빡이지 않는다.
- 모바일은 메뉴를 가로 스크롤 탐색 막대로 전환하고 남은 화면을 콘텐츠에 배정한다.
- 버튼·관리 드롭다운·탐색 메뉴는 한 줄을 유지한다. 너비를 압축해 글자가 세로로 내려가게 하지 않는다.

요약은 전체 계정, 회원 계정, 익명 러너, 이용 정지 수다. 검색/필터와 관계없는 전체 계정 기준이며, 목록 결과 수는 검색과 필터에 맞는 인원이다. 회원 계정은 `is_anonymous=false` 기준이며 이메일 인증 인원과 혼동하지 않는다. 실제 전환 이력을 수집하기 전까지 익명 전환율은 표시하지 않는다.

## 3. 테이블 최종 규칙 (사용자 수정 요구 우선)

**모든 헤더와 데이터 셀은 가운데 정렬한다. 숫자도 가운데 정렬한다. 한 셀에는 한 항목만 표시한다.**

### 러닝과 경험치 설정 표

- 설정 표는 셀 테두리를 `#9ea685`로 진하게 표시하고, 헤더 고정(sticky)에서도 테두리가 사라지지 않도록 `border-collapse: separate`를 쓴다.
- 셀 안 입력칸은 높이 38px, 가운데 정렬.
- 경험치 설정 아래에 **레벨별 필요 경험치** 표(레벨 · 누적 필요 XP · 이전 레벨에서 필요한 XP · 완주 기준 누적 거리 · 해금)를 둔다. 저장 전 입력값으로 즉시 계산한다.

### 검색·필터 툴바

- 검색창, 필터 select, 검색 버튼을 한 줄에 놓고 **높이를 모두 44px로 맞춘다.**
- 툴바 뒤에 배경색이나 박스를 넣지 않는다. 컨트롤 자체의 흰 배경과 테두리(#bfc2af)만 사용한다.
- select의 별도 레이블 대신 첫 옵션에 "가입 유형 전체"처럼 기준을 적고, 레이블은 스크린리더 전용으로 둔다.
- 문의·채팅 신고의 상태 필터도 같은 툴바 규칙을 따른다.

회원 목록은 다음 12개 독립 컬럼을 유지한다.

`No | 닉네임 | 이메일 | 가입 유형 | 권한 | 계정 상태 | 경험치 | 누적 거리 | 러닝 횟수 | 가입일 | 최근 접속 | 관리`

- No는 현재 검색 결과의 순번이며 페이지를 넘겨도 11, 12처럼 이어진다. 내부 사용자 ID가 아니다.
- **회원(실명) 계정을 먼저, 익명 러너를 뒤에 배치한다.** 같은 유형 안에서는 최근 가입 순이다. 정렬은 서버에서 한다.
- 닉네임과 이메일을 묶지 않는다. 가입일과 최근 접속도 서로 다른 셀로 유지한다.
- 표 외곽과 모든 셀에 가로·세로 보더를 적용한다. 색상은 `#bfc2af`다.
- **모든 관리자 표의 헤더는 공통 색상 #e3e8d6 하나만 사용한다.** 컬럼별로 다른 색을 쓰지 않는다.
- 본문은 단일 줄을 유지한다. 공간이 부족하면 글자를 세로로 꺾지 않고 표 영역에 가로 스크롤을 제공한다.
- 회원 행 높이는 64px, 셀 패딩은 상하 14px·좌우 16px로 유지한다.
- 숫자는 `tabular-nums`를 사용하고 XP/km/회 단위를 표시한다.
- 선택 행은 올리브 배경, hover 행은 크림 배경으로 표시한다. 가입 유형에 따라 행 전체를 칠하지 않는다.

## 4. 상태 배지

| 상태 | 배경·테두리 | 의미 |
| --- | --- | --- |
| 회원 / 정상 | 옅은 그린 배경·그린 테두리, #212121 텍스트 | 이용 가능한 회원 |
| 익명 / 일반 | 베이지 배경·테두리, #212121 텍스트 | 기본 분류 |
| 관리자 | 옅은 오렌지 배경·테두리, #212121 텍스트 | 운영 권한 |
| 이용 정지 | 옅은 빨강 배경·테두리, #212121 텍스트 | 이용 제한 |

색상만으로 의미를 전달하지 않는다. ‘정상’, ‘이용 정지’ 등 텍스트를 항상 함께 표시한다.
회원이라는 이유만으로 행 전체를 강조하지 않는다.

## 5. 관리 드롭다운과 React 모달

회원별 관리 셀은 ‘관리 선택’ 버튼과 펼침 메뉴(`AdminActionMenu`)를 사용한다. 네이티브 select는 펼친 목록을 운영체제가 그려 정렬을 맞출 수 없으므로 쓰지 않는다.

- 메뉴 너비는 220px로 고정하고, 항목은 [아이콘 18px | 작업 이름 | 사유 태그] 3칸 그리드로 같은 왼쪽 선에 맞춘다. 항목 높이는 40px.
- 실행할 수 없는 항목은 숨기지 않고 "러닝 중", "관리자", "러너 생성 전" 사유 태그와 함께 비활성으로 표시한다.
- 메뉴는 body로 포털해 표의 가로 스크롤에 잘리지 않게 하고, 화면 아래에 공간이 없으면 위로 연다. 바깥 클릭, 스크롤, ESC로 닫는다.
- 키보드: 열면 첫 항목에 포커스, ↑↓로 이동, Enter로 실행, ESC로 닫고 버튼으로 포커스 복귀.
- 표 안의 버튼(처리하기, 문의 열기 등)도 관리 선택 버튼과 같은 38px 높이를 쓴다.
선택 즉시 서버를 변경하지 않고 `react-modal` 기반 안내 모달을 연다.

| 작업 | 모달 내용 | 실행 조건 |
| --- | --- | --- |
| 상세 보기 | 회원 정보, 가입·접속 날짜, 최근 10개 러닝 | 읽기 전용 |
| 경험치 조정 | 현재 XP, 변경 후 총 XP, 레벨·해금 재계산 안내 | 러너 생성 완료, 진행 중 러닝 없음, 정수 0~1,000,000,000 |
| 이용 정지 | 제한되는 기능과 문의 접수 가능 안내 | 관리자 계정 제외 |
| 이용 복원 | 제한 해제 및 기존 기록 유지 안내 | 관리자 계정 제외 |

변경 작업은 2~500자 사유를 필수로 입력한다. 한 개의 모달에서 안내·입력·취소·적용까지 처리한다.
‘경험치 조정’은 더할 값이 아니라 **변경 후 총 경험치**라는 점을 강조한다.
적용 전까지 변경은 발생하지 않는다. 실행 중 버튼을 잠가 중복 요청과 중간 닫기를 막는다.
서버 오류는 모달 내부에 표시하며 입력값을 보존한다. 성공하면 모달을 닫고 목록을 다시 조회한다.

### 모달 영역 구조 (필수)

관리자 모달(회원 관리, 테스트 계정 만들기 등)은 **제목 영역 · 본문 영역 · 푸터 영역** 세 부분으로 구성한다.

| 영역 | 내용 | 규칙 |
| --- | --- | --- |
| 제목 영역 (`.admin-modal-header`) | 모달 제목, 닫기 버튼 | 높이 64px, 흰 배경, 아래 테두리. 제목 #212121 Bold 20px. 영문 eyebrow 등 보조 문구를 두지 않는다. 고정. |
| 본문 영역 (`.admin-modal-body`) | 대상 회원, 짧은 안내, 경고·입력 필드, 오류 | 패딩 24px. 내용이 길면 **본문만 스크롤**한다. 입력 검증 오류는 해당 입력 아래에 둔다. |
| 푸터 영역 (`.admin-modal-footer`) | 취소·실행 버튼 | 흰 배경, 위 테두리, 오른쪽 정렬, 버튼 높이 44px. 고정. 위험 작업(정지·삭제)의 실행 버튼은 `danger`. |

입력이 있는 모달은 `<form class="admin-modal-form">`이 본문과 푸터를 감싸 Enter 제출이 동작하도록 한다.

**목록의 작업 버튼(관리 선택, 처리하기, 문의 열기, 보기)은 모두 모달로 연다.** 표 아래에 편집 영역(div)을 펼치지 않는다. 문의 답변은 `AdminSupportModal`, 채팅 신고 처리는 `AdminReportModal`을 사용한다.

### 비밀번호 초기화

관리 선택 → 비밀번호 초기화. 이메일로 가입한 일반·테스트 계정만 대상이며 관리자와 내 계정은 제외한다.
초기화하면 비밀번호가 **`rundash123!`** 로 바뀌고 로그인 중인 기기는 모두 로그아웃된다. 모달 본문에 이 임시 비밀번호를 그대로 표시하고, 회원에게 로그인 후 마이페이지에서 바로 변경하도록 안내하라는 문구를 둔다. 사유는 필수이며 변경 이력에 남는다.

### 모달 접근성과 반응형

- `react-modal`에 앱 루트(`#root`)를 지정하여 배경을 스크린리더 탐색에서 제외한다.
- 제목과 설명을 ARIA로 연결하고 포커스를 모달 안에 가둔다.
- ESC·닫기·취소를 지원하며 배경 클릭으로는 닫지 않는다.
- 닫으면 관리 드롭다운으로 포커스를 복원한다.
- 작업 중에는 ESC와 닫기·취소를 비활성화한다.
- 최대 너비 620px, 높이는 뷰포트 안으로 제한하고 긴 내용은 모달 내부에서 스크롤한다.
- 모바일 화면 여백 12px, 본문 패딩 20px, 주요 버튼 높이 44px 이상을 확보한다.

## 6. 알림 (토스트)

작업 결과 알림("계정을 삭제했어요", "저장하지 못했어요" 등)은 화면 안의 div·p 문구가 아니라 **오른쪽 위 토스트**로 띄운다.

- `react-hot-toast`를 사용하고 `src/lib/notify.js`의 `notify.success / notify.error / notify.info`로만 호출한다.
- 위치는 오른쪽 위(헤더 아래 12px), 흰 배경, #bfc2af 테두리, 글자 #212121 Medium. 성공 아이콘은 올리브, 실패 아이콘은 짙은 빨강.
- 표시 시간은 성공 3.5초, 실패 5초.
- 토스트로 바꾸지 않는 것: 입력 검증 오류(필드 아래), 목록 조회 실패(다시 불러오기 버튼과 함께), 이용 정지 같은 지속 상태 안내.
- 토스트는 네이티브 `<dialog>` 위에 보이지 않으므로, 작업 결과를 알리는 모달은 `react-modal`을 사용한다.

## 6-1. 페이지네이션 (공통 컴포넌트)

모든 관리자 목록은 `src/components/Pagination.jsx`를 사용한다.

- **한 페이지 10건, 페이지 번호 10개 단위**로 보여준다. 예: 1~10, 다음 묶음은 11~20.
- 이동 버튼은 react-icons(Lucide)를 사용한다: « 이전 10페이지(`LuChevronsLeft`), ‹ 이전 페이지(`LuChevronLeft`), › 다음 페이지(`LuChevronRight`), » 다음 10페이지(`LuChevronsRight`).
- **현재 페이지는 원형 배경(올리브 #48522c)과 크림색 숫자**로 표시하고, 나머지 페이지는 숫자만 표시한다.
- 오른쪽에 **페이지 바로 이동** 입력창(번호 입력 → 이동)을 둔다. 범위를 벗어난 번호는 첫·마지막 페이지로 맞춘다.
- 이동할 수 없는 화살표는 비활성 규칙(배경 #e4e0d8, 점선 테두리)을 따른다.

## 7. 데이터와 로딩

검색·필터·페이지 나눔(10건 단위)은 서버에서 같이 적용한다. 필터 변경 시 1페이지로 돌아간다.
로딩, 검색 결과 없음, 러닝 기록 없음, 조회 실패를 각각 문장으로 설명한다.
로딩 중에는 요약 수치를 0명으로 오인시키지 않고 대기 표시를 쓴다.
민감한 변경은 기존 관리자 전용 RPC를 사용하며 클라이언트 상태만으로 권한을 판정하지 않는다.

## 8. 구현 파일과 배포 순서

- `src/screens/Admin.jsx`: 목록, 요약, 서버 필터, 작업 선택.
- `src/screens/admin.css`: 관리자 전용 스타일. 다른 러닝 화면과 분리.
- `src/components/AdminMemberModal.jsx`: react-modal 안내·작업 창.
- `src/components/AdminActionMenu.jsx`: 회원별 관리 메뉴.
- `src/components/Pagination.jsx`, `src/lib/pagination.js`: 공통 페이지네이션과 페이지 계산.
- `supabase/migrations/202611160001_admin_member_directory.sql`: 요약과 필터를 제공하는 관리자 전용 RPC.
- `supabase/migrations/202611160002_admin_paging.sql`: 회원·문의·신고·이력 목록 10건 단위, 회원 먼저 정렬.

1. SQL Editor에서 위 마이그레이션 두 개를 파일명 순서대로 먼저 실행한다.
2. 앱을 빌드하고 배포한다. 기존 `admin_members_list`는 유지되어 이전 배포도 계속 동작한다.
3. 관리자 계정으로 목록·필터·드롭다운·모달을 확인한다.

## 9. 검수 기준과 다음 단계

- 전체 회원이 10명을 넘어도 검색·필터 결과 수와 페이지가 일치하고, 회원이 익명보다 먼저 나와야 한다.
- 비관리자는 요약이나 회원 목록을 조회할 수 없어야 한다.
- 경험치 입력이 잘못되거나 사유가 짧으면 적용을 막는다.
- 진행 중 러닝은 경험치를 변경할 수 없고 관리자 계정은 정지할 수 없어야 한다.
- 모달에서 Tab 이동, ESC, 포커스 복귀, 오류 후 재시도를 확인한다.
- 375px 모바일 화면과 데스크톱에서 전체 영역 사용, 버튼 한 줄 유지, 표 스크롤과 모달 높이를 확인한다.
- 1차 적용 범위는 회원 관리와 공통 관리자 레이아웃이다. 문의·신고의 상태 배지와 작업 모달 통일은 다음 단계로 진행한다.
