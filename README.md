# Run dash

## 문의와 관리자 운영

헤더의 문의하기에서 버그 신고, 기능 제안, 계정 문의, 러닝 문의, 기타 건의를 접수합니다. 본인 문의만 조회하며 운영 답변과 처리 상태를 확인할 수 있습니다. 익명 사용자도 문의할 수 있지만 새 익명 계정으로 바뀌면 이전 문의를 볼 수 없습니다. 접수 간격은 계정별 60초입니다.

관리자는 헤더의 관리자 페이지 버튼으로 회원 검색과 이용 정지·복원, 회원별 최근 러닝 기록 조회, 총 경험치 조정, 문의 답변과 상태 처리, 변경 이력 조회를 할 수 있습니다. 변경 사유가 기록되며 진행 중인 러닝의 XP는 수정할 수 없습니다. 이용 정지는 러닝 시작과 보상 저장, 프로필 변경, 채팅 전송을 서버에서 차단하며 문의 접수는 허용합니다. Supabase 인증 계정 자체를 삭제하거나 비밀번호를 대신 변경하지 않습니다.

러닝 설정은 경험치 곡선과 km당 XP, 완주 보너스, 회원·익명 거리 상한, 익명 기본 능력치, 레벨 1~50의 페이스·체력·회복·부스터, 강도 3종, 보급소, 회복량, 리듬 판정과 점수, 메달 배치, 응원, 채팅 글자 수와 전송 간격을 포함합니다. 설정은 버전을 확인하여 저장하며 동시에 수정된 오래된 버전은 거절합니다. 다음 러닝부터 적용하고 서버가 시작 당시 설정을 보관해 기존 러닝의 보상 기준을 유지합니다. 경험치 곡선 변경은 기존 XP의 표시 레벨도 바꿀 수 있습니다. 최초 기본값은 `src/lib/settings.js`에 있습니다.

`202611140006_account_profile.sql`부터 `202611140009_admin_member_details.sql`까지 현재 프로젝트에 적용했습니다. 새 환경은 모든 마이그레이션을 파일명 순서대로 적용하세요. 관리자 지정은 신뢰할 수 있는 DB 운영자가 `public.admin_members`에 해당 인증 사용자 ID를 등록해서 처리합니다. 사용자 메타데이터나 이메일 문자열만으로 관리자 권한을 부여하지 않습니다. 관리자 자격 증명은 저장소와 빌드에 포함하지 않습니다.

React + Vite + React Three Fiber. Pretendard 기반 크림/올리브 디자인.
이메일 로그인/회원가입 및 Supabase 익명 인증을 사용하며, 정식 계정의 프로필과 러닝 기록은 실제 DB에 저장합니다. 익명 체험의 러너와 기록은 React 메모리에만 유지하고 새로고침하면 초기화합니다.

## Supabase 설정

1. 프로젝트 `yjlebedgsktdxacpasgt`의 SQL Editor에서 `supabase/migrations/202611140001_initial.sql`을 실행합니다. 신규 테이블 기준이며 기존 테이블이 있으면 스키마를 먼저 비교하세요.
2. Authentication → Sign In / Providers에서 이메일과 Anonymous Sign-Ins를 활성화합니다.
   회원가입 전 닉네임 중복 확인을 위해 `supabase/migrations/202611140002_signup_nickname_check.sql`도 실행합니다. 공개 함수는 중복 여부만 반환하며 테이블 접근 권한은 변경하지 않습니다.
3. URL Configuration의 Site URL에 운영 Vercel URL을, Redirect URLs에 운영 URL과 `http://localhost:5173`을 등록합니다.
4. `.env.example`을 `.env.local`로 복사해 Publishable key를 채웁니다. 현재 로컬에는 전달받은 공개 키를 설정했습니다.
5. `npm install`, `npm run dev`를 실행합니다.

브라우저에서는 Publishable key와 RLS를 사용합니다. DATABASE_URL, DB 비밀번호, service_role 키를 VITE_ 환경변수에 넣지 마세요.
익명 사용자도 authenticated 역할로 자신의 데이터만 접근합니다. 로그아웃/브라우저 데이터 삭제 후 익명 계정은 복구할 수 없습니다.
닉네임은 대소문자 구분 없이 고유하며 가용성 RPC는 다른 프로필 정보를 공개하지 않습니다.
러닝 결과의 모든 통계를 runs.details에 저장합니다. 점수는 클라이언트 계산값으로 경쟁용 검증은 별도 서버 구현이 필요합니다.
현재 코스의 다른 러너는 기존 시뮬레이션이며 실제 멀티플레이 연결은 별도입니다.

## Vercel 배포

Git 저장소를 Vercel에서 Import하고 Framework를 Vite로 선택합니다. vercel.json에 빌드 설정이 있습니다.
Environment Variables에 아래 두 값을 Production/Preview별로 등록하고 배포합니다.

- VITE_SUPABASE_URL: https://yjlebedgsktdxacpasgt.supabase.co
- VITE_SUPABASE_PUBLISHABLE_KEY: Supabase의 Publishable key

환경변수를 변경한 경우 재배포해야 합니다. `.env.local`은 Git에서 제외됩니다.

## 비밀번호 찾기 / 이메일 재인증

- 로그인 화면의 비밀번호 찾기는 Supabase `resetPasswordForEmail`을 호출합니다.
- 이메일 재인증 화면과 가입 완료 화면에서 `resend({ type: 'signup' })`로 가입 확인 메일을 다시 요청할 수 있습니다.
- 재설정 링크는 `/?auth=reset-password`로 돌아옵니다. 인증 세션을 확인하고 새 비밀번호·확인을 입력받아 `updateUser`로 변경합니다.
- 비밀번호 변경 후 로그아웃하여 새 비밀번호로 로그인하도록 안내합니다. 만료/실패한 링크에서는 새 메일을 요청할 수 있습니다.
- URL Configuration → Redirect URLs에 `http://localhost:5173/?auth=reset-password`와 `https://실제운영도메인/?auth=reset-password`를 등록하세요. 이메일 인증용 루트 URL도 등록해야 합니다.
- Email Provider의 Confirm email 설정과 메일 템플릿의 ConfirmationURL을 확인하세요. 운영용 이메일 발송에는 Custom SMTP 설정 및 발송 제한을 확인해야 합니다.
- 메일 요청 성공 안내는 계정 존재 여부를 노출하지 않으며, 화면에서 60초 재요청 대기를 제공합니다. 서버 발송 제한도 그대로 적용됩니다.
- 실제 이메일 수신 → 링크 열기 → 비밀번호 변경 → 새 비밀번호 로그인과, 인증 메일 재발송 → 인증 → 로그인을 운영 도메인에서 확인하세요.

러너 만들기는 화면 높이에 맞춰 외부 스크롤을 막고 오른쪽 폼 박스 안에서 스크롤합니다. 모바일에서는 미리보기 아래 폼에 내부 스크롤을 적용합니다.

## 성장 시스템

`supabase/migrations/202611140004_runner_growth.sql`은 현재 연결된 프로젝트에 적용했습니다. 새로운 환경에서는 앞선 마이그레이션 이후 한 번 실행하세요. 기존 기록에 경험치를 소급 지급하지 않고 새 러닝부터 성장합니다.

- 목표 페이스 직접 입력 대신 가볍게/꾸준히/도전하기를 선택합니다. 같은 강도도 레벨이 오르면 빨라집니다.
- 거리 1km당 100 XP, 완주 시 거리 XP의 20%를 추가 지급합니다. 중도 종료도 달린 거리만큼 지급합니다.
- 레벨별 기본 페이스/체력/회복 및 해금 표는 `docs/GROWTH_DESIGN.md`를 참고하세요.
- 부스터는 Lv.5 해금, 속도 +50%, 체력 12 소모, 종료 후 90초 재충전입니다. 버튼 또는 B로 사용합니다.
- 운영 빌드에서는 배속 선택과 배속 변경 동작을 제거합니다. 개발 환경에서만 10x/30x/60x를 테스트할 수 있습니다. 기본은 항상 1x입니다.
- 개발 배속은 왼쪽 아래 `개발용 디버그 모드` 버튼으로 패널을 활성화해야 표시됩니다. 패널을 끄면 1x로 복귀하지만 체험 기록 표시는 유지합니다. 배속과 레벨·체력 읽기값은 이 패널에 모았습니다.
- 한 번이라도 배속을 사용하면 해당 러닝 전체가 체험 기록이 되며 다시 1x로 돌아와도 XP와 누적 성장 거리를 지급하지 않습니다.
- 러닝 시작은 서버 세션을 생성하며, 종료 시 RPC가 기록 저장과 경험치 반영을 한 트랜잭션으로 처리합니다. 동일한 러닝 ID로 재시도하면 원래 보상을 반환합니다.
- 성장 테이블에는 본인 SELECT만 허용하고 XP 직접 수정과 runs 직접 INSERT를 차단합니다. 서버 시작 시간·레벨·선택 강도로 보상의 시간/거리 상한을 검사합니다.
- 현재 게임 동작과 점수는 클라이언트 시뮬레이션입니다. 서버 시간 검사는 빠른 조작 보상을 제한하지만 완전한 서버 게임 검증이나 경쟁용 부정행위 방지는 아닙니다.
- 다른 창에서 새 러닝을 시작하면 이전 창의 진행 중 러닝은 보상 저장할 수 없습니다.

검증: `npm test`는 실제 PostgreSQL 엔진(PGlite)에서 마이그레이션과 RLS/RPC를 실행하고, XP·레벨·부스터·재시도·배속 제외를 확인합니다. `npm run build`로 운영 빌드를 만듭니다.

## 이동 / 종료 확인

헤더·로고·로그아웃·로그인/회원가입·러닝 시작·화면 이동은 공통 확인 모달을 거칩니다. 취소와 Escape는 현재 화면에 머무릅니다. 같은 화면을 다시 누르는 동작과 의상/활동 카테고리 선택에는 화면 이동이 없습니다.

러닝 중 종료 또는 다른 메뉴 이동을 요청하면 즉시 일시정지합니다. 취소하면 이전 일시정지 상태를 복원하고, 확인하면 현재까지의 결과를 저장한 후 이동합니다. 저장 실패 시 재시도해도 보상은 중복 지급되지 않습니다. 자동 완주와 최초 세션 복원은 별도 확인 없이 진행합니다.

새로고침·탭 닫기·외부 페이지 이동에는 `beforeunload`로 브라우저 기본 확인창을 요청합니다. 브라우저 정책에 따라 사용자의 페이지 조작 이후에만 나타나며 문구는 브라우저가 정합니다.

## 매뉴얼 / 리듬 / 보급 / 코스

- 헤더의 원형 `?` 버튼으로 전체 매뉴얼을 엽니다. 리듬·점수·콤보·XP·보급·체력·부스터·채팅·구름과 단축키를 설명합니다. 러닝 중에는 일시정지하고 닫으면 원래 상태로 돌아갑니다.
- 리듬 판정은 바의 중앙입니다. 실제 표시와 판정이 같은 시간/위상을 사용하며 PERFECT ±0.09초, GOOD ±0.2초입니다. 한 주기에 한 번만 판정해 연타 중복 점수를 막습니다. 일시정지/탈진 회복 시 마커도 멈춥니다.
- 리듬 PERFECT 5pt, GOOD 2pt, MISS는 콤보 초기화입니다. 콤보당 아이템 점수가 10% 증가하고 최대 2배이며 XP와는 별개입니다.
- 보급소는 올리브 캐노피·카운터·쿨러·도로 콘·거리 간판으로 구성합니다. 물/젤 선택 UI는 남은 보급 구간과 수량, 회복량을 표시합니다. 첫 600m, 이후 1km마다 배치하며 코스 종료 80m 안쪽에는 새 보급소를 만들지 않습니다.
- 콤보/보급/메달/응원 점수는 왼쪽 상단으로 모았습니다. 구름 말풍선은 머리 오른쪽에 위치하며 설정/러닝 중 모두 보이기·숨기기를 지원합니다.
- 코스 미리보기는 풍경별 색상 스트립, 세로 타임라인, 실제 보급 위치, 완주 지점을 표시합니다. 긴 코스는 첫 10km를 보여주고 이후 순환을 안내합니다.

## 실시간 러너 라운지

`supabase/migrations/202611140005_runner_chat.sql`은 현재 연결된 프로젝트에 적용했습니다. 새 환경에서는 이전 마이그레이션 다음에 실행하세요. `race_messages`를 Supabase Realtime publication에 추가합니다.

- 러닝 중인 정식/익명 사용자가 같은 라운지에서 대화합니다. 최근 50개 메시지를 읽고 INSERT 변경을 구독하며, 재연결 시 중복 없이 합칩니다.
- 작성자는 서버에서 인증 ID로 결정합니다. 정식 계정 닉네임은 프로필에서 가져오며 클라이언트가 사칭할 수 없습니다. 익명은 검증한 닉네임과 익명 표시를 사용합니다.
- 서버에서 1~300자와 사용자별 2초 전송 제한을 적용합니다. 메시지 직접 INSERT 및 전송 제한 테이블 접근은 차단하고, RPC로만 전송합니다. 내용은 HTML로 실행하지 않고 텍스트로 표시합니다.
- Presence는 러닝 화면에 들어온 실제 계정만 추적합니다. 동일 계정의 여러 탭은 한 명으로 계산하고, 하나라도 달리고 있으면 달리는 인원에 포함합니다. 연습 캐릭터는 포함하지 않습니다. 연결이 끊기면 재연결 상태를 표시하며 유령 인원 수를 남기지 않습니다.
- 채팅을 숨겨도 구독과 인원 집계는 유지합니다. 러닝 화면을 나가면 구독을 해제합니다. 채팅 입력 중 게임 단축키가 실행되지 않습니다.
- 실제 프로젝트에 테스트 메시지는 전송하지 않았습니다. 전송자 검증·rate limit·길이·RLS는 로컬 PostgreSQL 테스트에서 확인했습니다. 실제 Realtime 연결과 Presence 집계는 브라우저에서 확인했습니다.
